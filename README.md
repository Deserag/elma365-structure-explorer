# ELMA365 Structure Explorer

Независимое frontend-приложение для изучения экспортированной структуры ELMA365. **Сервер, API-ключи и подключение к ELMA365 не требуются.** Сайт можно разместить как статический проект на GitHub Pages.

Интерфейс доступен в опубликованном веб-приложении после включения GitHub Pages.

## Что реализовано

- Интерфейс в стилистике ELMA365: панель разделов, приложения, страницы и отчёты.
- Импорт большого `structure.json` с разделами, полями, приложениями, модулями, решениями и процессами.
- **Повторный импорт без потери старой структуры:** приложения, поля, процессы, страницы и отчёты сопоставляются по кодам; отсутствующие в новой выгрузке элементы остаются в локальной структуре. У обновлённых элементов сохраняются неизменённые атрибуты.
- Поиск приложений по имени, коду или разделу. Переход в карточку из списка результатов.
- Поля со схемой типов, обязательностью, множественностью и ссылками.
- **Связи приложений:** входящие и исходящие, через какое поле и на какую коллекцию (в том числе `SYS_COLLECTION`). Переход к связанному приложению.
- Бизнес-процессы и их версии — если они присутствуют в JSON.
- Группы и права: отображаются **только реально экспортированные** атрибуты доступа. Отсутствующие настройки не подменяются выдуманными.
- Генерация тестовых записей по типам полей: индивидуально и для всех приложений. В режиме всех приложений заполняются ссылки на созданные тестовые записи.
- Экспорт объединённой структуры в JSON и экспорт тестовых данных выбранного приложения.
- Хранение исходной структуры, истории импортов и тестовых записей в **IndexedDB** браузера.
- Адаптивная разметка, поддержка мобильных устройств, поиск через `Ctrl+K`.

## Запуск локально

Достаточно Node.js 18+; зависимости устанавливать не нужно.

```bash
npm start
```

Откройте `http://localhost:4173`. Либо запустите `python -m http.server 4173` в корне проекта.

## Публикация на GitHub Pages

1. Создайте **новый публичный репозиторий** `elma365-structure-explorer` на GitHub.
2. Загрузите в ветку `main` **весь код из этого проекта**, включая `index.html`, `app.mjs`, `data.mjs`, `styles.css`, `.nojekyll`, каталог `assets`.
3. На GitHub откройте **Settings → Pages → Build and deployment**. Выберите `Deploy from a branch`, затем `main` и `/(root)`, сохраните.
4. Откройте адрес вида `https://<github-login>.github.io/elma365-structure-explorer/`.

Приложение использует относительные URL и маршруты через `#`, поэтому не требует `base`-конфигурации и server-side rewrite.

## Безопасность и ограничения

**Не коммитьте рабочий `structure.json` в публичный репозиторий.** В поставке включены только искусственные демонстрационные разделы. Пользователь загружает свой JSON непосредственно в браузере, и он не отправляется на GitHub или какой-либо API. Весь импортированный JSON и тестовые данные остаются в IndexedDB *текущего браузера и домена*. В приватном/инкогнито-режиме либо при очистке данных сайта они могут пропасть. Сохраняйте резервную копию через «Экспорт» (структура) и «Скачать JSON» (данные каждого приложения).

Приложение не запускает реальные бизнес-процессы ELMA365 и не создаёт записи в рабочей CRM. Определение связей зависит от полей-ссылок, действительно указанных в JSON. Настройки доступа, отсутствующие в экспорте, восстановить из него невозможно.

## Проверка

```bash
npm test
npm run check
```

Тесты проверяют слияние повторных экспортов, сохранение полей и процессов, разрешение связей, генерацию тестовых данных и доступы. Интеграционная проверка проводилась на полном `structure.json` (39 разделов, 235 приложений, 6 424 поля и 370 уникальных бизнес-процессов).

## Файлы

- `index.html` — стартовая страница.
- `styles.css` — адаптивный интерфейс.
- `app.mjs` — навигация, поиск, импорт/экспорт, страницы приложений.
- `data.mjs` — модели JSON, слияние, связи, генерация и IndexedDB.
- `server.mjs` — локальный dev-сервер без внешних зависимостей.
- `tests/` — автоматические тесты.

Этот проект не является официальным продуктом ELMA365.
